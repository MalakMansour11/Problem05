Why a "mismatch count" leaks a secret

This mirrors a real vulnerability pattern: a login check that is supposed to say only "right" or "wrong" instead tells you how close your guess was, by printing the number of mismatched characters. That single number turns a brute-force problem into an easy one — you can solve the password one character at a time.

Why some regex patterns can "explode"

Some regular expressions have internal ambiguity: the same input can be split into pieces in many different ways. When a match ultimately fails, the regex engine may try every one of those ways before giving up — so processing time can blow up as the input grows, even though the input itself isn't especially long. This is called ReDoS (Regular Expression Denial of Service), and it's one real instance of an Algorithmic Complexity (AC) time attack: a crafted input pushes an algorithm toward its worst case instead of its typical case.
